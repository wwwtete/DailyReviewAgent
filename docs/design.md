# 每日复盘智能体设计

用户要求：Codex、飞书、Git、浏览器；默认读取可发现且可访问的数据，黑名单拦截；独立脚本/程序和定时任务，不依赖聊天上下文。

采用 Python 3.9+ 命令行程序、SQLite 事件库、磁盘规则文件、macOS launchd。每次从磁盘加载配置与历史，采集器直接读取本地日志和浏览器历史、调用 Git 和飞书 CLI，模型只收到已经过滤的数据，无工具权限。复用现有 Codex 自定义 Responses 服务配置；也支持环境变量配置。

备选：依赖当前聊天的自动任务不满足独立运行要求；全天屏幕录制没有必要且不能可靠反映成果，首版不用。

黑名单按来源 ID、项目路径、名称通配符、域名和 URL 匹配。识别资源需要读取最小元数据；禁读 Codex 会话正文、飞书会话消息和 Git 仓库内容在读取前过滤。浏览器先查访问 ID 与 URL，过滤后再查标题。任务/日程列表接口可能返回正文，过滤只能在收到列表后立即丢弃，此限制必须明示。支持关闭整个来源。已有事件在报告前重新过滤；黑名单变化后不复用旧模型摘要，旧报告仍是文件需用户明确清理。

首版飞书覆盖全部可见群聊/私聊的当日消息、个人任务快照、日历和已结束会议元数据；不自动抓取所有云盘正文或附件。浏览器覆盖 Chromium 系、Firefox、Safari 可访问历史，不能覆盖无痕或已删除历史。Git 默认发现用户目录及 Codex 工作目录内仓库，读取提交元数据、变更文件和当前状态，不读取所有源文件或执行仓库脚本。

日报正文建议使用今日关键战报、经验与教训沉淀、工作流提效方案、AI使用方式总结与提升；标题可按内容增减、改名或调整顺序，SOP四字段仅作建议，不设置生活模块。关键战报提取核心完成项与关键数据/产出及实际状态，无计划或工时依据就直接陈述事实，不强行量化。正文通常300–2000中文字，有落地SOP时最多3400字；资料少就更短。流程优化为核心，避免流水账和过度解读。程序不再强制四模块结构，JSON、行动字段与证据审查仍保留。来源覆盖和索引移至独立附录。无可复盘内容直接简短输出；模型失败仅输出失败状态，不倾倒日志。SQLite 持久化行动，模型不能自行标记行动已执行。

用户确认暂无黑名单，按空黑名单运行；每天北京时间10:00复盘昨天完整自然日。先完成合成数据测试，再真实验证和启用调度。模型服务原配置 gpt-6.1-terra 返回 model_not_found；本程序独立选用同服务列出且连通性验证通过的 gpt-6.1-sol，不改全局配置。
