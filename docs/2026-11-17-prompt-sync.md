# 2026-11-17 Prompt 与输出校验同步

本次保留用户编辑的主 `INSTRUCTIONS` 原文，按用户确认同步程序、说明和桌面对比任务。

- 四模块标题和 SOP 四字段为建议，允许增减、改名、重排；程序不再因这些结构差异拒绝报告。
- 不设置生活模块。使用 AI 模块但无有价值内容时写“暂无”。
- 核心产出不限制三项；无计划或工时依据时直接陈述事实，不强行量化。
- 正文通常 300–2000 中文字，有落地 SOP 时最多 3400 字；资料少就更短。
- JSON、非空正文、行动字段、证据引用和独立事实审查要求保留。

README、设计说明、对比输入的 presentation 与桌面对比任务说明同步上述规则。实际自动任务提示词与任务说明正文核对一致，原调度、模型、项目和状态保留。

## 验证

全套 `python -m unittest discover -s tests` 共 189 项通过。回归覆盖自定义标题、模块增减与重排、无 AI 内容、非法行动引用、无事实报告、灵活结构下的真实引文校验。暂存区源码导出至独立目录后再次运行全套测试，确认不依赖生产配置或数据库。

真实模型使用合成记录、临时数据库及独立运行目录验证，经过报告生成和事实审查：

| 场景 | 实际结果 |
| --- | --- |
| 无计划工时的单点文案修正 | 正文 177 字，无编造比例；不强凑经验或 SOP，AI 模块为“暂无” |
| 明确两项计划、完成一项，含工时和已采用的链接委派 | 正文 636 字，保留任务状态与工时事实；提供可复用 Prompt，并区分已采用方式与待采用建议，未冒称真机验收通过 |

首次真实验证发现审查模型将 `lessons` 文本写入 `claims[].text`，与程序要求该字段逐字匹配正文的校验冲突，导致审查耗尽。审查提示词现已明确：检查全部字段，但引文清单只摘录 `report_markdown` 连续原句，其他字段有问题通过审查失败及原因反馈。程序引文校验未放宽；修正后两个场景均在一次生成及一次审查后通过。

合成数据和模型日志仅存本机被忽略的 runtime 目录；验证不覆盖正式日报，不写生产事件库，不调用通知或 Typora。以上验证确认规则与生成链路可用，不代表模型每次输出完全相同。
