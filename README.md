# 每日复盘智能体

这是独立运行的本地程序。采集、过滤、数据库、模型调用和定时逻辑均由磁盘上的程序执行，不需要保持聊天窗口，也不依赖某个 Codex 会话的上下文。

## 运行方式

从 Git 仓库首次部署时，先复制脱敏配置示例并填写本机路径、身份及黑名单：

```bash
cp config.example.json config.json
```

示例默认关闭采集；检查配置并确认数据范围后，将 `collection_enabled` 改为 `true`。飞书 CLI 和模型凭据在本机单独配置。`config.json`、运行数据库、日志、报告、研究产物、备份、虚拟环境及生成的 launchd 配置均由 `.gitignore` 排除，不进入版本库。

本机已建立 `.venv`，通过 `bash run.sh` 执行。首次迁移到其他机器时执行：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

配置在 `config.json`。本机 CLI 绝对路径写在配置中，迁移时需要修改。模型凭据运行时读取现有 Codex 配置或环境变量，不复制到此项目。首版模型是当前服务已验证可用的 `gpt-6.1-sol`，不会修改全局 Codex 模型设置。

实际后台运行副本位于 `~/Library/Application Support/DailyReviewAgent`，避免 macOS 阻止 launchd 从“文稿”目录启动。此交付目录中的 `installed`、`config.json`、`reports`、`runtime` 是指向运行副本的链接，`run.sh` 也转发到运行副本。因此修改这里的配置会影响下一次执行。源码副本便于阅读，部署代码修改时应同步到 installed/daily_review。

```bash
# 检查依赖；可选 --probe-model 测试真实模型
bash run.sh doctor --probe-model

# 采集并分析今天；日期按 config.json 的 Asia/Shanghai
bash run.sh run
bash run.sh run --date 2026-11-10

# 仅采集，不调用模型；部分失败会返回非零，但已读事件会保存
bash run.sh run --no-ai

# 不重新采集，只使用已存事件重新生成指定日期报告
bash run.sh report --date 2026-11-10

# 查看状态、记录主观感受、跟踪改进行动
bash run.sh status
bash run.sh note '今天精力较低；需求变更导致返工，未上线。'
bash run.sh actions
bash run.sh action ACTION_ID active
bash run.sh action ACTION_ID done --note '三个任务均提前确认验收，未发生理解偏差返工'

# 安装/卸载 macOS 用户定时服务
bash run.sh install-schedule
bash run.sh uninstall-schedule
```

报告保存在 `reports/YYYY-MM-DD.md`，来源索引和采集诊断单独保存在 `reports/YYYY-MM-DD.sources.md`，SQLite 保存在 `runtime/events.sqlite`。记录与日志权限设为仅当前用户可读写。合成样例在 `examples/`，明确不是你的实际工作。

## 报告阅读方式

正文建议使用以下四个模块，标题可按内容增减、改名或调整顺序；通常300–2000中文字，有落地SOP时最多3400字。资料少就更短，不为达到篇幅扩写：

- 📌 **今日关键战报**：提取核心完成项与关键数据/产出及实际状态（已完成/推进中/未闭环），不限制为三项。无需强行量化完成率或时间利用率；若无计划或工时依据，直接陈述事实即可。
- 💡 **经验与教训沉淀**：默认精选一项改变下次做法的任务方法或技术/业务判断；不足可空。单次事件不推断用户盲区/习惯；跨日或跨项目独立事件重复才考虑个人模式。同任务多会话不算独立证据，AI漏做测试不能归为用户能力问题。专门针对AI使用的经验放AI模块。
- 🚀 **工作流提效方案（SOP / 工具 / 流程重构）**：默认精选一项。B优先提供已准备并审查的项目适配草案，附入口和验证范围；A备用提供阻碍、具体步骤及责任。建议用 **[优化场景]、[瓶颈根因]、[具体落地方案]、[落地工具/载体]** 四字段表达，字段形式与顺序不作硬性校验；瓶颈可包括有依据的重复、等待、返工或执行偏差。AI负责建设/执行/核验，用户只作必要的一次性准备。无价值足够机会就空，不增加人工清单维护。
- 🤖 **AI 使用方式总结与提升**：围绕用户具体任务，沉淀有事实依据的Prompt写法、工具选择、任务委派、验收方式及改进；给可复用片段、入口或步骤。已采用与待验证建议分清，不复述AI执行流水账，不与前两模块重复展开。采用此模块但无有价值的内容时，正文写“暂无”。

不设置生活模块。正文不展示采集数量、长事件ID、哈希、无助于执行的原始路径或来源清单；附录保留追溯能力。SOP执行必需的命令、配置位置和建议新增的文件名可写入正文。整天没有可复盘事项时直接输出简短结果，不调用模型编写空洞建议。程序校验非空正文、JSON与行动字段、证据引用，不再因模块名称、数量或顺序不同拒绝报告；独立事实审查仍覆盖全部正文。

## 数据覆盖

| 来源 | 首版读取 | 边界 |
|---|---|---|
| Codex | 本地 state 数据库发现的全部普通及归档会话；当天用户/助手消息及工具结果 | 只覆盖本机可用日志，不包括没有同步到本机的其他主机/云端会话；数据格式变化会报告失败 |
| 飞书 | 全部可见群聊和私聊当日消息、个人任务、主日历日程、历史会议元数据 | 不会自动下载所有云盘正文、附件或会议逐字稿；线程回复仅覆盖列表返回的内容，未另行遍历线程；默认全部可见会话可能耗时较长 |
| Git | 用户目录下自动发现的仓库，以及 Codex 工作目录；提交元数据、作者、变更文件名和当前未提交状态 | 自动发现跳过 Library、依赖/缓存目录和符号链接，额外仓库可加到 roots；不读取源码 diff、不执行仓库代码、不拉取远程 PR/CI；非用户作者的提交不自动算作本人贡献 |
| 浏览器 | 当前禁用 | 不采集、不将旧浏览器事件回灌到历史研究或日报 |

默认全部读取的含义是：对上述已实现且可发现、可访问的来源，不需要逐项白名单。它不意味着绕过系统权限，或支持这些产品全部资源类型。

## 黑名单

空数组默认允许。字段拼写错误会停止运行，避免误以为规则生效。规则支持大小写不敏感的名称/ID通配符；`paths` 使用实际绝对路径，匹配该路径及子路径；`domains` 自动包含子域名。

示例（替换配置对应字段，以下都是占位符）：

```json
{
  "blacklist": {
    "sources": [],
    "paths": ["/absolute/path/to/private-project"],
    "names": ["*私人*", "*机密项目*"],
    "codex_ids": ["conversation-uuid"],
    "project_ids": ["codex-project-id"],
    "lark_chat_ids": ["oc_example"],
    "lark_ids": [],
    "domains": ["private.example.com"],
    "urls": ["https://example.com/private/*"],
    "git_remotes": ["*private-repository*"],
    "browser_profiles": []
  }
}
```

- `sources` 可禁用 `codex`、`git`、`browser`、整个 `lark`，或 `lark_messages/lark_tasks/lark_calendar/lark_meetings`。
- `lark_ids` 可禁用任务/日程/会议 ID。`lark_chat_ids` 用会话 ID 阻止消息请求。
- 黑名单在正文读取前检查来源元数据；识别资源仍需读取最小元数据。浏览器锁库时会创建仅当前用户可访问的临时完整数据库副本，用后删除；URL过滤发生在标题提取前。这不是对硬盘底层页的“零读取”隔离。
- 飞书任务/日程/会议列表可能直接附带内容，无法在服务器返回前按任意名称规则过滤；收到后立即丢弃，不入库、不进入模型。如不接受该限制，应禁用对应整个来源。
- Git 需要读取变更文件名来判断子目录规则；涉及禁读路径的整个提交跳过，随后才读取提交消息。不会读取禁读文件正文。
- 允许记录若明确包含禁读 ID、路径、名称或域名，也会保守丢弃。不同平台的项目别名不能自动可靠关联，需分别写入路径、会话 ID、名称/域名规则。
- 报告生成时重新执行当前黑名单，规则变化后旧报告摘要与旧行动不再进入模型。**以前生成的报告文件和已有数据库原始记录不会因新增黑名单自动物理删除。** 如需清理历史，应明确指定；清理文件会影响已有归档。
- 浏览器 URL 参数已经丢弃，新增只针对历史 URL 查询参数的规则无法追溯匹配旧记录；建议按域名或路径阻止。

## 调度与故障恢复

launchd 每五分钟唤醒脚本检查是否到期，未到期不采集也不调用模型。按主人最后确认的时间，每天北京时间08:00启动昨日00:00–24:00完整自然日复盘，通常在08:00–08:05之间启动，报告生成取决于全量采集和模型耗时。与主机显示的时区无关。

服务在用户登录后运行，电脑关机/休眠时不执行，恢复后按持久化日期顺序补跑，每轮最多处理3天，不永久跳过更早日期。首次自动运行从配置的 start_date 开始。

锁文件阻止两个CLI运行同时采集。每条事件有稳定ID，重复采集覆盖而不重复计数。完整采集后删除已消失的当日快照；部分失败保留先前事件并明确标记覆盖不完整。失败来源保留补采日期，六小时后重试；模型失败一小时后重试。旧日期的未提交状态、被源系统删除的记录和已经丢失的浏览历史不能事后恢复。

模型按批次读取过滤后的事件，只能生成文本，未提供任何工具。新任务不续接旧模型会话；历史经验和行动显式从 SQLite 读取。最多新增一个实验，行动只有用户通过CLI确认后才会改变执行状态。

为了控制日志分析成本，单条超过6000字符的事件默认只把首尾发送给模型，来源附录标注省略条数，正文仅用一句提示部分记录覆盖，完整记录仍保存在事件库。可调整 `model.max_event_chars`；省略部分不保证被分析。

模型服务不可用时只输出简短的“未完成AI分析”状态，不向用户倾倒原始日志。数据源失败写入来源附录，正文保留必要的范围提示，不将读取失败当作没有工作。第三方模型服务的可用性、配额及计费沿用现有服务设置。

## Codex 增量事实归档（2026-11-10）

2026-11-11 修复：按会话和物理文件身份分别保存读取游标，扫描 sessions 与 archived_sessions 下同一会话的相关记录文件；旧游标迁移时保留证据 ID。文件移动后证据关联按 file_id 更新，避免路径复用造成错引。扫描错误保留具体原因，worker 返回非零失败状态。

浏览器来源目前按用户要求暂时禁用：不采集、不做浏览器诊断探测，也不把数据库已有浏览器事件加入日报；旧记录仍保留。日报先检查 Codex 归档完整性，阻塞时等待补齐，避免反复重采飞书。

日报采用紧凑事实表：每条事实正文、状态、时间和经验候选保留，项目/会话元数据只存一份；短 ID 映射到完整证据库，模型需要时可回查。超出 240000 字符才进行分批事实归并，每轮检查所有输入 ID 恰好被覆盖一次。日期.input-audit.json 保存输入数量、体积、映射与归并覆盖记录。语义归并仍可能有模型误差，覆盖校验不等于语义正确性的证明。

Codex 数据源现改为结构化事实库，日报不再把旧的 Codex 原始事件作为模型输入。北京时间 **08:00** 复盘昨天（按最新要求调整）。

2026-11-11 个人主体修正：归档优先保留用户的约束、取舍、理由、纠正和验收反馈，经验候选必须直接引用用户原话并关联用户证据事实；仅有助手或工具证据的旧候选在日报入口过滤。事实输入保留证据角色及用户原话，避免将AI实施过程归因为用户能力。注入的AGENTS.md/环境元数据不作为本人行为证据。旧版日报经验不再回灌个人成长历史；不改写历史原文及证据ID。

- `Stop` / `SessionEnd` / `Interrupt` Hook 只检查黑名单并登记任务，不调用模型、不注入上下文、不让 Codex继续执行。
- 独立 launchd 服务 `local.daily-review-archive` 监听任务目录，并每60秒补查新增记录。每批最多12个提取任务；初次回填从2026-11-09开始，失败任务指数退避重试。
- 以持久化字节游标增量读取，同一轮按北京时间自然日拆分。归档仅含 `facts` 与 `experience_candidates`。无工作事实时两个数组为空；没有足够证据时经验候选为空。
- 每项事实引用原文，程序验证引用存在且是原文连续片段；助手自述不能单独支撑 `verified` 状态。经验候选必须关联事实，明显建议措辞和日报模块内容会被拒绝。语义是否充分仍受模型能力限制，引用校验不等于因果证明。
- 过滤非文本媒体编码，保留文本证据和原始会话索引。不会把截图编码交给文本模型，也不会声称看过图像。超长文本完整分片，不使用首尾截断；不会保存模型内部推理。
- 黑名单在发现资源、读取原文、发送模型、读取归档与回查证据时生效。旧归档随当前规则重新过滤；原始存储不自动物理删除。
- 日报阶段才综合启用来源的工作事实，按建议模块生成复盘与行动建议。需要核查时可请求最多3个合法归档事件的证据片段，最多回查一轮。
- 数据库存储位置为 `runtime/events.sqlite`：`codex_cursors` 保存断点、`codex_jobs` 保存待处理片段与结构化结果。任务完成后仍保留证据片段；原文完整版本保留在 Codex 会话文件。
- 未处理任务、扫描错误或扫描状态过期会反映为来源不完整，不会伪装成“没有工作”。已生成日报对应的归档补齐后会标记重算。

**首次 Hook 信任**：Codex 的产品机制要求用户在 **设置 → Hooks** 审阅并信任3个 `DailyReviewAgent fact archive` 处理器。程序保留原有通知 Hook，不写信任数据库、不绕过审查。未信任时分钟补漏程序仍独立工作。官方说明：https://learn.chatgpt.com/docs/hooks#review-and-trust-hooks

在本目录终端运行：

```bash
bash run.sh archive-status
bash run.sh archive-work
bash run.sh archive-work --force
bash run.sh archive-evidence 'codex:archive:<任务ID>:<事实序号>'
```

`archive-work` 通常由后台自动执行；`--force` 仅用于手动跳过失败重试等待。`archive-evidence` 只接受合法归档事件ID并检查当前黑名单。`install-archive` 可幂等重新安装本程序的 Hook 和后台服务。

归档完整性是日报发布条件：如果目标日Codex仍有待处理记录、扫描错误或扫描状态过期，写出 `日期.pending.md` 并延后结论生成，不以部分历史猜测当前状态。已存在的旧报告保留。归档补齐后调度自动重试。Codex结构化事实不会再次经过旧的600字分批摘要；极端情况下超过输入上限会明确失败，不静默丢弃事实。

## 报告完成后的桌面提醒

定时 `tick` 首次成功保存正式日报后会执行以下动作；手动 `run` / `report` 需显式加 `--notify` 才请求执行：

1. 通过 macOS 通知中心提示“每日复盘已完成”，显示报告日期，不展示工作内容。
2. 使用 `/usr/bin/open -a Typora` 打开对应日期的 Markdown 主报告。

`config.json` 中 `desktop.notify` 和 `desktop.open_typora` 分别控制通知及打开，默认均为 `true`。
同一日期的主报告路径只提交一次成功的通知和打开请求，状态保存在SQLite中，程序重启后继续去重；内容更新、黑名单变化及后续补采均保留已成功记录，静默更新报告。自动生成及桌面重试都只在北京时间08:00及之后执行；到点后首次成功的报告可以延迟提醒。
手动执行 `run` 或 `report` 默认静默，需加 `--notify` 才请求桌面提醒与打开，例如 `bash run.sh report --date 2026-11-10 --notify`。此参数仍遵守去重，不强制重复已成功的动作。
归档等待、模型失败和仅采集记录不会触发。两个动作单独记录成功或失败；失败动作由后续定时检查按5分钟间隔重试，已成功动作不重复。文件被替换或黑名单变化时取消旧的未成功请求；新的成功报告可以更新请求，只补试未成功的动作。
报告成功保存或复用缓存后，即确认本次读取的归档修订，不再要求Git等其他来源全部采集完成；生成期间出现的新修订保留。失败的报告保留修订并遵守重试等待，其他来源仍按原有间隔补采，不会每五分钟重算旧报告。

通知使用系统 `osascript`，本机通知来源已确认为“脚本编辑器”（com.apple.ScriptEditor2）。用户要求通知持续显示直到手动关闭，因此需在“系统设置 → 通知 → 脚本编辑器”中将通知样式设为“提醒”（Alerts），而非会自动消失的“横幅”（Banners）。这一样式由macOS控制，脚本不能通过display notification指定；脚本不会主动关闭通知。通知权限与专注模式仍决定是否展示，命令成功只代表系统已接收请求。Typora需保持安装。电脑休眠/未登录时沿用原有任务补跑机制，唤醒登录后处理。

## 跨日研究（2026-11-12）

工作事实严格对应报告所标自然日。近7日事实按增量发现研究机会，具体候选按项目/会话/任务链接等稳定标识关联回查近30日；同项目仅为上下文，不作为同根因或个人模式证明。历史日报只用于去重与回访。未完成机会和明确反馈跨日保留，原始证据通过ID回查；不将整个历史窗口拼入日报。

研究使用同一SQLite的research_items/research_seen，记录证据、状态、尝试次数、重试时间、产物版本/哈希、审查范围、反馈与发布日期。独立launchd服务每10分钟处理一批，逐批消化首次积压；每轮最多研究一个机会，每个机会最多6次受控工具调用，工具结果逐步持久化，失败后从检查点续跑。发现阶段失败也不会饿死已有研究。日报不等待研究，不受其独立锁影响。08:00继续复盘昨天。首次历史积压可能需要多轮，未完成产物留待后续日报。

受控研究工具可回查合法证据、读取证据指向项目内源码/说明、获取公开HTTPS文档。不会读取浏览器历史，不执行任意shell，不改其他项目，不发消息。公开文档请求是主动研究，与浏览器采集无关。当前B产物支持Markdown/文本/JSON草案，由独立模型调用进行结构及事实适配审查；**不代表真实业务、设备验收或实测收益**。需要执行新脚本/设备才能证明的机会按A备用方案交付，不能冒充已验证自动化。

- 安装独立服务：bash run.sh install-research
- 运行研究：bash run.sh research-work（默认截至北京时间昨天）；可加 --date 2026-11-11
- 查看队列：bash run.sh research-status
- 标记采用：bash run.sh research-feedback RESEARCH_ID done --note '已采用'
- 停止推荐：bash run.sh research-feedback RESEARCH_ID stopped --note '不适用/已掌握'

产物在运行目录的 artifacts/机会ID/；含草案与research-audit.json。只发布正文确实采用的成果，避免每天重复；改动产物后哈希不一致不再发布。黑名单/禁用来源在历史读取、证据回查、项目文件与发布前重新检查；策略变更后的旧研究结果不直接发布。


## ChatGPT 桌面端并行对比

API 路径继续运行，统一北京时间每天 08:00 复盘昨天。桌面端作为独立第二条生成路径，只在 ChatGPT 聊天中显示报告，不写本地报告、不回写行动/研究状态、不触发 Typora。桌面任务需要另行在 ChatGPT 桌面端创建；准备脚本不代表任务已创建。

本地生成器将最终模型调用所用的材料保存到 runtime/comparison-inputs/YYYY-MM-DD.json（只保存输入，不含 API 生成的报告或凭据）。如 API 请求补充证据，最终供桌面读取的输入包含同一批补充；API 请求失败时仍允许桌面独立生成。读取命令不调用 API，不执行采集，不更新 SQLite，不持有日报主锁：

```bash
/bin/bash '/Users/weiwang/Library/Application Support/DailyReviewAgent/run.sh' comparison-input --wait-seconds 1200
```

默认按北京时间计算昨天，可用 --date 指定日期。退出码 1 且 reason=waiting_for_api_input 表示同日材料尚未就绪；不能拿其他日期替代。读取前重检当前黑名单/来源配置，变化后拒绝输出旧输入。等待 API 完成材料准备意味着两条路径都是 08:00 启动，而不是承诺同时完成。最多等待 20 分钟后如仍无材料，桌面端只说明原因；原 API 后台照常继续。输入快照会复用现有压缩，不新增原始历史读取。

两条路径共用材料及内容规则。桌面端仅将 JSON 输出格式改为直接呈现 Markdown。对比主要看事实准确、个人归因、新增方法价值、SOP 可执行性和冗余程度；不能将同材料差异一概归因为模型本身，因为运行环境和输出格式也不同。任务说明见 docs/chatgpt-desktop-comparison-task.md。
